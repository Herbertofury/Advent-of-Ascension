On 2026-10-16, the official default branch is `1.21`, HEAD `7919b5fe48599e6105c5740937ce36c36ef21d16`. The existing retained modern source matches every one of 14,236 Git blob objects and all 46 changelogs in that exact official tree. Enderloom's complete official provider observation contains 99 version records and identifies **AoA3 1.21.1-3.7.16.1**, file `7424722`, as the newest production release. This is a dated observation, not a permanent latest-version constant or proof that every modern change is already in the private Forge 1.20.1 candidate.

## Canonical merge and stable-world rules

- Use one canonical playable identity when exact source/registration/behavior evidence proves an old/new match. Prefer the verified better modern model, texture, behavior and dependencies together.
- Preserve unique historical content and distinct variants. Upstream removal is an explicit restoration/reconciliation decision. Never infer sameness from names or filenames.
- Preserve every proven Enderloom improvement, source authority, registered ID, save record and optional user choice. Retain an alias/migration where an actual rename is proven.
- Use improved worldgen for new chunks. Existing chunk replacement needs an explicit migration with snapshot, compatibility tests and rollback.
- Require native client/server, progression, multiplayer, optional integration, migration and equivalent-work performance evidence for the changed scope.

## Latest direction to reconcile, not blindly copy

For 3.7.16.1, review permission safety, firing and scope corrections, projectile/AI fixes, crash fixes, spawn balancing and expanded Extraction support. For 3.7.16, review data-driven equipment configuration, projectile rewrites, newer art, portal safety, persistence/sync repairs, broader ammo interoperability and world-generation/performance changes. Each target needs a native adapter and tests; a 1.21-only API or removed class must not be activated blindly in another target. See the pinned source changelogs for complete details.

## Drift and execution

The repository gate checks upstream and the complete wiki intake on relevant changes and daily. It reports changed branch/head/changelogs/releases/tags; it does not silently merge code or delete historical content. Before a meaningful Enderloom implementation/promotion pass, use the existing complete official/provider freshness observer. The whole-project native acceptance runner now validates that observation against the accepted lock before mutation. Direct Studio entry-point coverage remains a separate integration task.
