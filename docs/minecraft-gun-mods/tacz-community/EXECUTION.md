## Release and access distinctions

- TCPL has an original creator release/showcase and a public author forum resource listing version 26.3.31. The forum requires login for download; exact current file and pricing remain unconfirmed.
- RSCA is attachment-heavy but the creator explicitly names an additional gun, IMC-7274. Its ten underbarrel accessories and thirteen sights are not counted as new guns. All-version-free wording is the creator's statement.
- EMI Classic is a distinct nostalgic adaptation of an older Flan's Mod EMI arsenal, not EMX. The historical 1.7.10 reference is not assigned as current TaCZ compatibility.
- TROL's transforming/biological and flywheel-steam firearms have original creator showcases. Earlier Cold Wind/Winter Is Coming names remain lineage, not duplicates. Its old public beta download is not represented as the later 2.1 showcase edition.
- bare has a named public gunpack download. The separate banger grenade pack's LR dependency is not copied onto the firearm pack.
- The author explicitly renamed IFCD to COD Collector's Edition. Distinct Peacekeeper MK1, KRIG-6 and AK117 content is separated from cosmetic variants. Newer TaCZ 1.1.6+ creator wording is not converted into an invented Minecraft/loader pair.
- Boonie Bears' October 25, 2026 public remake is an open test, with TaCZ 1.1.8 plus Gunsmith stated by the creator. Its chainsaw segment is not counted as firearm content.

Video views, likes and creator followers are not converted to gunpack downloads or ratings. Unknown public popularity metrics remain unknown.

## Research coverage and limitations

The new route inspected 191 exact public creator-video metadata records, including all relevant exposed episodes in the selected author-owned collections. Every record has a recorded disposition. Many records concern already listed packs, older versions, creator lineages or non-gun content; 191 is not a count of distinct new gunpacks.

Twenty broader Bilibili keyword queries were attempted. Provider blocking/rate limiting prevented terminal traversal; no query is falsely reported complete. Thirty-five search hits and the access failures are retained as evidence. Public forum pages were readable through the web route while the research runner received access failures; forum authentication was not bypassed.

A separate filename-indexed GitHub manifest search returned 138 indexed hits through one connector observation, but the Actions research route was rate-limited and did not finish reading those manifests. It is explicitly recorded as incomplete, with zero claimed manifest files read. Provider-directed second/millisecond waits were handled without retrying unchanged failures indefinitely. A different connected file-content search was also inspected; its loader/documentation/server-workspace results are not a substitute for a completed filename manifest census.

The final challenge preserved a Kaito Kid-inspired playing-card-gun source lead, a Hexalunar AWP-generation script and a World of Kivotos provenance workspace without inventing packaged releases. See challenge-review.json. The first describes a Rhino-derived appearance replacement and has no published GitHub release; the latter two do not establish a separately released firearm pack from the retrieved evidence.

This is a broad new creator-source investigation, not proof that all private, unlisted or blocked packs have been found. Unresolved leads remain explicit and available for future qualification.

## Verified publication-race recovery

The first publication job 121284465091 correctly stopped when the public explorer still served the prior 2,417-record dataset. The Wiki, offline apps and frozen rebuild had passed. Creating the publication marker had superseded the preceding Pages build; the matching source's new Pages build was still running. This was a deployment-identity race, not a catalog or app defect.

Recovery: hold the main source head fixed, retain the exact run/data hashes, allow the matching Pages build to advance, then rerun the existing failed publication job through GitHub's supported rerun action. Do not repeatedly create marker commits, which can cancel the deployment being awaited. The successful rerun required the exact new parent and TaCZ hashes and passed all unchanged acceptance gates. No data reset, weakened check or repeated research was used.

This recovery applies only when the source is already verified and the public site demonstrably serves an older dataset. A genuine build failure, mismatching current hash or runtime regression requires its own causal repair rather than this deployment wait/retry route.
