# Weapon base reuse and internal-animation standard

Reviewed 2026-10-27. Applies to every AoA weapon, not only firearms. This is a selection and acceptance register, not permission to redistribute an unreviewed pack.

## Quality first, reuse before rebuilding

Every completed weapon needs outstanding exterior presentation and functioning animated game internals at a strong TaCZ-pack standard. Prefer an appropriate high-quality existing base, reusable project asset or rough mesh when it reduces rework without compromising the selected concept. A base is a starting point, not a reason to retain the wrong silhouette or resource behavior.

Before selecting a donor, compare concept fit, accessible source geometry, named movable parts, rig quality, animation ownership, interruption recovery, texture quality, first/third-person hand fit, native compatibility and measured runtime cost. Popularity, a polished video or many polygons does not establish quality. Do not rank a base as best before inspecting its actual files and behavior.

## Per-weapon internal-motion acceptance

- Name every visible moving part and its role in the fictional supply/resource-to-emitter sequence. Magical or biological internals need coherent game behavior rather than an invented conventional magazine.
- Tie firing motions to confirmed shots, not raw input; do not advance parts for rejected or duplicate events.
- Test empty/partial resource states, interrupted reload or recovery, switching, sprint/aim transitions, repeated input and save/load.
- Show internal part motion only where the selected design exposes it; invisible parts still need clearance if modeled. Avoid gratuitous detail that harms performance without a visual/gameplay purpose.
- Keep authoritative resource use, projectile events, audio and animation in agreement. Cosmetic finishes must not silently change mechanics.
- Verify exact assets, native stack, hands, sockets, animation ownership and collision evidence. Rendered concept art and successful export are not native acceptance.

These are fictional game-asset requirements, not real firearm construction specifications.

## Permission handoff

For each candidate, retain author, official source, exact file/version/hash, license text, per-asset exceptions, planned edits, redistribution destination and attribution requirements. Public availability, installation permission and permission to modify/redistribute are distinct.

If the intended reuse is not clearly covered, keep the candidate **permission_required** and ask the user to request permission. Provide the exact asset, author, source link and requested scope: modifying mesh/rig/animations/textures, publishing modified source and distributing the resulting pack, including any commercial restrictions. Record the response and scope before copying it into a distributable derivative. Do not contact authors or claim their endorsement without authorization.

No request is needed merely to keep a reference link. If a license already covers the intended reuse and its conditions can be met, record that evidence instead of unnecessarily asking the author again.
