# Restoration roadmap

## Phase 1 · Establish the accepted content union

Pin legacy and modern originals, enumerate all accepted features, identify same-ID redesigns, retain removed-feature candidates separately, and reconcile the current Enderloom session. Preserve original archives and the last known working artifact; avoid duplicate whole-project backups.

## Phase 2 · Restore the primary target through Enderloom

Use shared semantic transformations and explicit project-specific rules with source fingerprints. Resolve mappings, loader APIs, registries, dependencies, rendering, networking, worldgen and persistence. Fix the earliest causal error. A generated tree manually edited until it compiles is not the final conversion product.

## Phase 3 · Close gameplay chains

Prioritize complete loops: realm access → exploration → encounter → resource → equipment/skill progression → return/save. Then complete the remaining roster without placeholders. Verify client/dedicated/integrated behavior, optional integrations and changed resource packs.

## Phase 4 · Prove the packaged game

Hash the actual JAR. Run packaged linkage checks, native client/server scenarios, full feature inventory, multiplayer, save/restart/migration and equivalent-work performance. Document failures without deleting features.

## Phase 5 · Clean replay and supported matrix

Reproduce from original inputs in a clean generated workspace using the normal Studio controls. Only then expand to other accepted version/loader cells. Mark unsupported cells with exact blockers; do not equate architecture support with a working release.
