# Undead Herald banner exchanges · 1.12.2

**Minecraft 1.12.2 · AoA 3.3.6.** The released Herald defines **22 realm-conditional exchanges and four common exchanges**. It never chooses all 26 as one ordinary list: a resolved context gets **four or five source-defined offers**.

<img src="https://raw.githubusercontent.com/Herbertofury/Advent-of-Ascension/main/docs/previews/legacy-1.12.2/inherited-undead_herald-thumb.webp" width="144" height="144" alt="Undead Herald source-model reference">

## Use the right realm context

1. Open the [historical Trading Desk](https://herbertofury.github.io/Advent-of-Ascension/trade-explorer.html?v=1.12.2&vendor=aoa3%3Aundead_herald). The unfiltered Herald view is a catalog of all 26 definitions, not a simultaneous shopping list.
2. Choose **Herald realm**. The control includes the four common exchanges plus the one conditional exchange for a supported realm. The URL preserves the selected context. Clear the search and other filters to see the complete source list.
3. Bring **ten of the specified currency for one banner**. In the Overworld, the conditional Void Banner exchange uses Silver Coins; the other twenty-one conditional contexts use their listed realm tokens. Do not substitute a similarly named token.
4. For Ancient Cavern, Immortallis, the End or an unmapped/null dimension lookup, the checked method adds only the four common Silver Coin exchanges.
5. Treat these as source defaults. Spawning, progression access, world configuration, GUI behavior, save/reload and modpack interactions still need live verification.

## Fixed lists, stock and disappearance

The released isFixedTradesList method returns true. The common and selected conditional entries are added to that fixed list. They use the same legacy two-stack recipe constructor as ordinary offers: its initial uses value is 0 and its default maximum is 5 for stackable outputs or 1 otherwise. The surrounding trader behavior matters, so these constructor fields are not a universal restock rule. See [historical trading and use-limit caveats](https://github.com/Herbertofury/Advent-of-Ascension/wiki/Trading-and-Traders-1.12.2).

The canDespawn override becomes true only when **ticksExisted > 72000**. It is false at 72000 and true at 72001. That is an eligibility predicate, not a command to remove the NPC at an exact wall-clock time; the surrounding entity/despawn behavior and tick rate still apply.

## Why the original generic parser excluded this trader

The earlier literal-method parser intentionally rejected the dimension lookup and switch. This addition decodes the released synthetic enum-switch map, verifies each branch jumps to the common tail, and checks all 26 recipe expressions against pinned source. It preserves the original 337 non-Herald offer semantics rather than flattening conditional branches into unconditional stock.

- 25 enum arms are mapped in the synthetic switch table.
- 22 arms add one realm-specific offer.
- Ancient Cavern, Immortallis and the End jump directly to the common tail.
- A null lookup also jumps to that same tail.
- The common tail always adds Creation, Energy, Soul and Blood banners.

The browser’s realm selector is a documentation filter. It does not inspect your current game world or claim the selected dimension is implemented in your Enderloom build.
