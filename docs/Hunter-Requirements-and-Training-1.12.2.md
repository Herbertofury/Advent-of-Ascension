# Hunter: requirements, training and loot eligibility

> Historical Minecraft 1.12.2 / AoA 3.3.6. These are released configuration defaults and selected callback rules. A server configuration or inter-mod registration can change them. No live game test is claimed.

## Start training

1. Check your Hunter level and choose an accessible target at or below it from the catalog below.
2. Open its creature card to inspect the available biome/dimension evidence, combat statistics and ordinary loot table. Location tags are evidence categories, not guaranteed spawn coordinates.
3. Defeat the target with player-linked kill credit. The selected death callback requests its registered positive Hunter XP.
4. For ordinary drops, use a player-attributed kill and meet the separate recently-hit and level checks. A pet kill can follow a different reward path.
5. Treat the listed XP as a base request. Shared XP settings and modifiers can change the final award. Do not infer the fastest training route from XP per kill alone.

## Three separate checks

| Check | Released behavior | Practical consequence |
|---|---|---|
| Attack permission | Registered exact entity classes use the player’s Hunter requirement; a player-owned tameable resolves to its owner. Creative bypasses the level gate. | An owned pet does not automatically bypass its owner’s level. |
| Death XP | The server death callback accepts a player or a tameable with a player owner, then requests positive registered Hunter XP. | Pet credit can qualify for XP independently of ordinary drops. |
| Ordinary drops | For a Hunter creature, the selected drop callback clears and cancels drops unless recently hit, the damage true source is a player, and that player is Creative or meets the requirement. | A tameable true source fails this ordinary-drop player check even when death XP has player-linked credit. |

The selected attack helper allows a null attacker and unregistered targets through its own gate. For a registered target with a non-null attacker that cannot resolve to a player, it rejects the attack. These helper rules do not certify every damage path, event order or external mod interaction.

The shared level helper returns true when skills are disabled. This bypasses that level comparison; it does not remove the separate recently-hit and player-source requirements in the inspected drop callback. The shared XP system must still be evaluated separately.

Ordinary LivingDropsEvent contents are the scope of the drop rule. This is not a claim that every custom reward, direct item spawn or other mod’s reward system uses the same event.

## Configuration and compatibility

- Default registration text has the form `aoa3:anemia lvl:1 xp:23.1`.
- The parser clamps required levels to 1–100 and XP to a nonnegative float range. It resolves the entity registry ID and requires an EntityLivingBase class.
- The Hunter registry keys exact classes. Subclass inheritance is not assumed.
- The selected registration method keeps the first registration for a duplicate class. Configuration and inter-mod registration order therefore matter when diagnosing competing entries.
- A mob missing from this default catalog is not proof that a customized server cannot register it as a Hunter creature.
- The Hunter armor class declares level 100 and a 0.3 Hunter XP modifier in its full-set callback. That declaration is not a live certification of every equipment or XP interaction.

## Troubleshooting checklist

- Cannot hit a target: compare the effective server registration and your Hunter level, then inspect the attacker or pet-owner identity.
- XP but no ordinary drops: check the death damage’s true source, recently-hit state and the separate drop callback. Pet credit is a particularly important case.
- Different XP from the table: check server overrides, XP settings and active modifiers before assuming the table is wrong.
- Different mobs require Hunter on your server: compare configuration and inter-mod registrations, including duplicate-class ordering.
- Test level one below / equal to / above the requirement, Creative, skills disabled, owned and unowned tameables, environmental kills, projectiles and multiplayer credit.
- Test event cancellation and custom direct-spawned rewards separately from ordinary drop-list behavior.
