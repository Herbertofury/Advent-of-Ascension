**Inspected artifacts:** AoA 3.6.11 for Minecraft 1.16.5 and AoA 3.7.1 for Minecraft 1.20.1. Each release has 78 covered gun registration factories, giving **156 release-specific item-card panels**. The two artifacts are analysed separately; modern 1.21.1 values are not copied into older cards.

For the older edition, use the separate [78-gun 1.12.2 reference](https://github.com/Herbertofury/Advent-of-Ascension/wiki/Gun-Constructor-Inputs-and-Recoil-1.12.2). Its constructor values and base recoil getter differ; do not transplant this table into that release.

## Read a historical item card

Open one of the release links below, then expand **Historical gun inputs · damage, timing and durability**. The panel lists the literal damage, durability, firing-interval and recoil arguments passed by the released registration factory, plus a resolved literal fire-mode getter where available.

These are constructor inputs rather than the newer `GunStats` components. Subclass logic, ammo consumption, enchantments, player state and the actual projectile still need separate analysis. Do not treat the table as measured final damage, DPS or a promise that two versions behave identically.

The panels are lazy and reuse the already loaded selected-release inventory data. Opening or reopening them does not request an additional stat file or scan your game.

## Recoil: a useful version-specific warning

In both inspected released `BaseGun` classes, `getRecoilModifier()` returns approximately **0.35**. That is separate from the recoil argument passed to an individual constructor. Minigun, for example, receives a recoil argument of 1.5, while the inspected base getter still returns 0.35.

The UI shows both facts with different labels. Do not silently replace one with the other, label the constructor argument as degrees or assume it is the value used by every runtime recoil path. An overhaul that starts using a formerly unused argument can change weapon feel and needs compatibility/balance testing.

## What matches across these two releases?

For the 78 matching registered IDs, the four selected constructor inputs and resolved literal firing-mode result match between the two inspected archives. This is a narrow comparison of those fields only. It does not establish equal ammunition rules, sounds, projectile effects, rendering, enchantments, cooldown handling or whole-mod compatibility.

Source pins are context; the numerical table is taken from each named released artifact.

The reader follows bootstrap-linked registration factories and accepts the selected four-numeric-argument gun signatures. It records constructor class hashes and method bytes without executing Java. Fire modes are resolved only from straight literal boolean getters along the inspected class hierarchy. The separate base recoil getter is also read from the released class.

Ammunition and special behavior are deliberately not borrowed from the modern component table. Those need their own historical method analysis. Shotguns, cannons, snipers, staves and other weapon families remain separate coverage; this is not a declaration that every weapon is fully documented.

AoA artwork and mechanics: Tslat and contributors. Independent original reference layout and explanations. No runtime acceptance or performance result is implied by matching numbers.
