# Enderloom integration · one reusable conversion project

![Conversion evidence stages](proof-pipeline.svg)

The existing Enderloom goal is a finished AoA mod delivered through the studio, not a stand-alone rescue script. Continue the canonical project and its accepted primary target.

## Pipeline

Original inputs and rights/provenance → persistent conversion session → content/behavior census → mapping and ABI lineage → semantic migration plan → dependency/toolchain lock → generated target → build/datagen → packaged linkage → native game checks → verified artifact → clean replay.

## Architecture contract

- One semantic project with shared source and loader/version overlays.
- Reusable fixes in the canonical Enderloom/Dev Kit owner, backed by a failing-before/passing-after regression.
- Exact owner/name/descriptor and invocation semantics, not name-only remapping.
- Explicit dependencies and optional-mod presence/absence tests.
- Stable content identity, save migration and resource ownership.
- Resumable jobs that reuse valid evidence and invalidate only changed inputs.
- Normal Studio Create/Convert/Repair/Play-test/Install controls that call real backend behavior.

A source file count, scaffold, successful compiler invocation or toolkit self-test cannot substitute for the full AoA gameplay gate.
