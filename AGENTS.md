# Advent of Ascension development rules

- Follow `development/living-upstream-policy.json`; Tslat and contributors remain credited.
- Use the complete wiki checklist and keep the atlas intact. A documented feature is not proof of a working merged feature.
- Refresh official default branch, every changelog, GitHub releases/tags and the official production release before a meaningful implementation or promotion pass. Enderloom owns the canonical project and version graph.
- Prefer verified newer models/textures/behavior/worldgen for proven semantic equivalents. Keep one canonical playable identity, preserve distinct variants and restore unique historical content. Never match by title alone.
- Preserve all prior verified improvements, registered IDs, saves and unknown extension data. Apply new generation to new chunks; require explicit migration, backup and rollback for existing chunks.
- Require native client/server, progression, multiplayer, migration, optional compatibility and equivalent-work performance evidence for the affected scope. Keep unsupported cells and unfinished union gates open.
- Keep vanilla hearts as the default and every optional AoA health mode.
- Preserve source provenance and original bytes. Write authored changes as UTF-8.
- Publish our original tooling and factual evidence; repository access is not a redistribution waiver for original AoA code/assets or modified JARs.
- Existing Enderloom authority order remains primary: next-generation stack contract, universal version graph, conversion ecosystem directive, then challenger research.
